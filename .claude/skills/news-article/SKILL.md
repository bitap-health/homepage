# お知らせ記事の追加・編集

## 最初に必ず確認すること

記事を作る前に、次の2点をユーザーに確認する。答えが出ていれば聞き直さない。

1. **記事の日付**（フォルダ名になる。原則としてイベントの実施日／完了日）
2. **公開するか、限定公開にするか**
   - **公開** … 一覧とトップページに出る。通常はこちら
   - **限定公開** … URLを知っている人だけが読める。**先方の公開許可を待っている記事はこちら**

## 作るもの

日付が 2026/08/03 の場合、次の3つを用意する。

```
news/20260803/
├── content.md     原稿（担当者が編集するのはこのファイル）
├── index.html     実際に表示されるページ
└── images/        20260803_1.jpg, 20260803_2.jpg …
news.json          一覧に登録する（日付の降順で正しい位置に挿入）
```

## content.md の書き方

```
---
date: 2026/08/03
tags: 登壇情報, 事業事例
title: タイトル
thumbnail: 20260803_1.jpg
---

本文の段落。空行で段落を分ける。

【見出し】

⚫︎箇条書きや料理名

> 引用（参加者の声・主催者コメント）

<!-- 2col -->
![](images/20260803_1.jpg)
![](images/20260803_2.jpg)
<!-- /2col -->
```

## index.html の作り方

**既存の記事をそのまま雛形にする。**直近の記事（`news/20260803/index.html` など）をコピーし、
日付・タイトル・本文だけ差し替える。ヘッダーとフッターは全記事で共通なので触らない。

**雛形から本文を差し替えるときは、末尾に前の記事の写真ブロックが残りやすい。**
`<div class="img-2col">` が意図した数だけかを必ず確認する。
`<div>` の開きと閉じの数が一致しているかも確認する。

本文の対応関係：

| content.md | index.html |
|---|---|
| 段落 | `<p>…</p>` |
| 【見出し】 | `<p><strong>【見出し】</strong></p>` |
| ⚫︎項目 | `<p><strong>⚫︎項目</strong></p>` |
| > 引用 | `<blockquote>…</blockquote>` |
| 2col / 3col | `<div class="img-2col">` / `img-3col` |
| URL | `<a href="…" target="_blank" rel="noopener noreferrer">` |

## タグ（記事の種類）

**タイトルに `【】` は書かない。**記事の種類は `tags` に分けて持たせ、
一覧カードと記事ページにタグとして表示する。

使うタグは次の9つ。**この一覧にないタグを勝手に増やさない。**
必要そうなときはユーザーに確認する。

| タグ | 使う場面 |
|---|---|
| 事業事例 | ケータリング・メニュー監修・セミナーなど、実際の受注案件 |
| 登壇情報 | イベント・講義での登壇 |
| メディア出演 | テレビ・記事・インタビュー |
| 受賞 | コンテスト等での受賞 |
| 採択 | 助成金・プログラムへの採択 |
| クラファン | クラウドファンディング関連 |
| 開催報告 | BitaP主催イベントの報告 |
| 会社情報 | 設立・認定ベンチャーなど、会社そのものの動き |
| 御礼 | 節目の挨拶 |

1記事に2つ付けてよい（例：登壇もした事業事例は `登壇情報, 事業事例`）。
**並び順は content.md の `tags` に書いた順がそのまま表示順**になる。

content.md はカンマ区切りの1行、news.json は配列で持つ。

```
content.md   tags: 登壇情報, 事業事例
news.json    "tags": ["登壇情報", "事業事例"]
```

記事ページ（index.html）では日付の上に置く。

```html
<div class="tags center"><span class="tag">登壇情報</span><span class="tag">事業事例</span></div>
<p class="detail-date">2026/08/03</p>
<h1 class="detail-title">タイトル</h1>
```

`<title>` と `og:title` にも `【】` は入れない。

### 絞り込みバー（news.html）

お知らせ一覧には、タグで記事をしぼり込むバーがある。
**バーは news.json から自動で作られる**ので、記事を足すだけで新しいタグも並ぶ。

ただし**並び順だけは `news.html` の `TAG_ORDER` が持っている。**
タグを新設したときは、ここにも追記する（書き忘れたタグは末尾に回る）。

```js
const TAG_ORDER = ['事業事例', '登壇情報', 'メディア出演', '受賞', '採択',
                   'クラファン', '開催報告', '会社情報', '御礼'];
```

しぼり込むと URL が `news.html?tag=事業事例` になり、その状態を共有できる。
トップページ（新着6件）にはバーを出さない。

## news.json への登録

日付の降順を保つ位置に挿入する。

```json
{
  "date": "2026/08/03",
  "tags": ["登壇情報", "事業事例"],
  "title": "…",
  "image": "news/20260803/images/20260803_1.jpg",
  "link": "news/20260803/",
  "fit": "contain",      // 任意。下記参照
  "public": false        // 任意。限定公開のときだけ付ける
}
```

### fit（一覧カードでの写真の収まり）

カードの枠は4:3。**既定は枠いっぱいに拡大**（`cover`）で、余白が出ない。
**BitaPロゴなどの図版は全体が見えるべき**なので `"fit": "contain"` を付ける。
写真でも、拡大すると内容が大きく欠ける場合（縦長など）は `contain` にしてよい。

### public（公開の範囲）

- **付けない** … 公開。一覧とトップに出る
- **`"public": false`** … 限定公開。一覧・トップから消えるが、URLを直接開けば読める

## 限定公開にするときの追加作業

`news.json` に `"public": false` を付けるだけでなく、記事ページにも2つ入れる。

1. `<head>` に検索避け
   ```html
   <meta name="robots" content="noindex, nofollow">
   ```
2. `<body>` の直後にプレビューであることを示す帯（既存の限定公開記事からコピーする）

## 公開に切り替えるとき

ユーザーから「公開して」と言われたら、次の3つを戻す。

1. `news.json` から `"public": false` の行を削除
2. 記事ページの `<meta name="robots" …>` を削除
3. 記事ページ冒頭のプレビューの帯を削除

## 写真の扱い

- **HEIC（iPhoneの形式）はブラウザで表示できない。**必ず変換する
  ```
  sips -s format jpeg -Z 1600 元ファイル.HEIC --out news/20260803/images/20260803_1.jpg
  ```
- **横1600pxを上限**にする。サイト上の最大表示幅は840pxなので、これで十分きれいに出る
- 枚数に応じた並べ方：1枚→そのまま／2枚→2col／3枚→3col／4枚→2col×2／6枚→3col×2
- **写真がまだ無い記事**は、`images/bitap_logo.png` を `20260803_1.png` としてコピーし、
  `news.json` に `"fit": "contain"` を付ける

## 書き方の作法（既存記事に揃える）

- 事業事例の記事は次の順で書く
  1. いつ・どこで・誰が主催の何というイベントか
  2. どんな参加者が何人集まったか
  3. BitaPが担当した範囲（メニュー企画／ケータリング手配／ポップ制作／当日運営サポート など）
  4. 主催者・参加者のコメント（引用ブロック）
  5. フードテーマと根拠（論文があれば引用を添える）
  6. メニュー各品の説明
  7. 料理作成の協力先
  8. 締めの一文とお問い合わせフォーム
- **ケータリングのついでに短く登壇した場合、登壇のために見出しを立てない。**
  3の段落の末尾に1文添えるのが既存の書き方
- 箇条書きの記号は `⚫︎` に統一する（`●` は使わない）
- **本文に推測を書かない。**分からない項目は本文中に
  `【要確認：内容】` と明記し、あとで差し替えられるようにする

## 最後に必ず行う確認

```
・記事ページが開けるか（404がないか）
・タイトルに【】が残っていないか（h1・<title>・og:title・news.json）
・tags が既存の9種類のどれかになっているか
・タグを新設したなら news.html の TAG_ORDER にも足したか
・記事内の画像・リンクがすべて表示されるか
・<div> の開きと閉じの数が一致しているか
・news.json の日付の並びが降順のままか
・限定公開なら、一覧とトップに出ていないこと
```
